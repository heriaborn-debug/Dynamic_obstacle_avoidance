# M20 局部障碍点云

## 基于可见性证据的时序体素融合

### 摘要

轮足机器人在真实地形中运动时，局部避障点云往往比单帧感知更难处理。机器人自身在平移、转弯、俯仰和侧倾，激光雷达还会受到遮挡、漏点和稀疏回波的影响。如果只使用当前帧，障碍边缘容易闪烁，细小物体可能时有时无；如果简单叠加若干历史帧，虽然画面会变“浓”，却容易产生拖影，并把已经离开的障碍继续留在规划空间中。

本项目实现了一套运行在 AOS 104 上的局部三维障碍证据地图。它接收 `/LIDAR/POINTS`、`/IMU` 和 `/lio/robo/odom`，输出 `/m20/local_mapping/evidence_cloud`，供 NVIDIA NX 上的通行性分析和局部规划使用。算法首先利用 IMU 建立重力对齐坐标系，使上下坡和机身倾斜不会把地面逐帧叠厚；随后利用里程计把上一时刻的地图变换到当前机器人坐标系，使历史障碍跟随机器人运动得到正确补偿；最后在体素中持续维护“这里像不像障碍”以及“这里是否已被证明为空闲”两类证据。

这套方法并不是固定累积 3 帧、5 帧或 10 帧点云。它累积的是空间状态，而不是原始帧数。只要一个体素仍在局部范围内，并且没有得到足够强的自由空间证据，它就可以继续存在；当当前激光明确穿过该位置，或者连续多帧没有回波时，它的占用证据才会下降。因此，地图的记忆长度由“可见性和证据”共同决定，而不是由一个生硬的滑动窗口决定。

系统效果较好的关键，在于它没有把“看不见”和“不存在”混为一谈。当前回波与历史体素重合时，体素被继续增强；当前射线穿过历史体素而在更远处命中时，说明该位置已经空出来，可以快速清除；若当前回波位于历史体素之前，则说明历史障碍可能只是被遮挡，应当保留；若整条射线没有回波，则先等待连续多帧确认，再进行较弱的清除。这样的非对称策略符合避障任务的风险特征：障碍出现要快，障碍消失要有依据，短暂漏点不能立刻把真实障碍擦掉。

从工程角度看，该方法把坐标一致性、时间稳定性、遮挡判断和实时性放在了同一个处理链路中。它使用原始点云判断空间是否可见，避免预处理误删回波后错误清图；使用滤波后的点云写入地图，减少孤立噪声成为障碍；处理线程只保留最新待处理帧，避免计算落后时延迟不断累积。最终得到的不是一团简单变厚的点，而是一张能够增强、保留和清除的局部障碍状态图。

需要说明的是，本目录记录的是 104 上当前实现的源码快照。上述优势可以由代码机制解释，但尚不能替代固定数据集上的定量对比。自由证据的非线性扣分、长期遮挡体素的淘汰以及细杆等稀疏目标的保留能力，仍值得通过 rosbag 回放和实机实验进一步验证。

## 1. 这套程序在做什么

程序维护一张以机器人为中心、Z 轴与重力方向一致的局部体素地图。地图范围约为机器人周围 `8 m × 8 m × 1.8 m`，XY 方向体素尺寸为 `4.5 cm`，Z 方向为 `6 cm`。机器人本体附近的点会被排除，最终只发布占用证据达到阈值的体素，点云的 `intensity` 字段保存其占用分数。

一次完整处理可以概括为：

```text
读取最新点云、IMU 和 ODOM
        ↓
把点云旋转到重力对齐坐标系
        ↓
把历史体素补偿到当前机器人坐标系
        ↓
用原始点云判断历史体素是重合、空闲、遮挡还是无回波
        ↓
用过滤后的当前点云更新体素占用证据
        ↓
发布稳定的局部障碍点云
```

这里最重要的认识是：输出虽然仍然是一帧 `PointCloud2`，内部维护的却不是普通点云列表，而是带有时间记忆的空间状态。

## 2. 方法原理

### 2.1 先稳定坐标，再谈多帧融合

多帧融合首先要解决的不是“累积多少帧”，而是“不同帧中的同一障碍能否落在同一位置”。设 IMU 给出的机体到世界旋转为 \(R_{w\leftarrow b}\)，其航向角为 \(\psi_{\mathrm{imu}}\)，程序构造重力对齐旋转：

\[
R_{g\leftarrow b}=R_z(-\psi_{\mathrm{imu}})R_{w\leftarrow b}.
\]

这一处理消除了 yaw，只保留与重力方向有关的 roll 和 pitch。机器人在坡面上俯仰或侧倾时，点云的竖直方向仍然稳定，地面不会因为姿态变化被融合成厚厚一层。

接下来，程序根据 ODOM 把上一帧局部地图变换到当前局部坐标系：

\[
T_{g_t\leftarrow g_{t-1}}
=T_{w\leftarrow g_t}^{-1}T_{w\leftarrow g_{t-1}}.
\]

例如机器人向前移动了 0.1 m，原先位于前方 2.0 m 的静态障碍，在当前机器人坐标系中应当位于 1.9 m。运动补偿会把历史体素移动到 1.9 m，而不是同时留下 2.0 m 和 1.9 m 两层点。这里直接决定了累积后的点云是“稳定”还是“拖影”。

### 2.2 体素保存的是证据，不只是坐标

空间被离散成体素后，每个体素不仅保存平均位置，还保存占用分数 `occupancy_score`、自由分数 `free_score`、累计命中数 `hit_count`、最后命中帧 `last_hit_frame` 和连续无回波帧数 `consecutive_free_frames`。

当前帧在同一体素内再次命中时，占用证据增加，自由证据得到缓解。稳定障碍会在数帧内迅速达到分数上限，因此偶尔漏掉一帧不会立刻消失。只有当自由空间证据持续出现时，占用分数才会被削弱；分数低于删除阈值后，体素才真正从地图中移除。

这相当于为点云加入了一种具有迟滞的短期记忆。它既能降低单帧噪声带来的随机跳变，又能在环境发生真实变化时逐步纠正历史状态。

### 2.3 用射线关系解释“为什么没看到”

程序把每个传感器视场划分为 `640 × 40` 个方位角—俯仰角栅格，并在每条角度射线上记录最近回波距离。对历史体素进行投影后，比较其距离 \(r_v\) 与当前最近回波 \(r_n\)。距离容差会随距离增大：

\[
m(r)=0.06+0.015r,\qquad f(r)=0.10+0.020r.
\]

由此得到四种有实际语义的情况：

- 若 \(|r_v-r_n|\le m(r_v)\)，当前回波与历史体素重合，说明障碍仍然存在；
- 若 \(r_v+f(r_v)<r_n\)，射线已经穿过历史位置并在更远处命中，说明该位置是明确自由空间；
- 若 \(r_n+m(r_v)<r_v\)，当前近处回波挡住了历史位置，说明它只是暂时被遮挡；
- 若射线上没有回波，信息不足，连续 5 帧后才启动较弱的清除。

这四种状态是整套算法最亮眼的部分。普通多帧拼接只知道“过去这里有点、现在这里没点”，而本方法进一步判断“没点究竟是障碍消失、被挡住，还是雷达暂时没有返回”。只要这个区别被建立起来，点云稳定性和动态清除能力就不再必然冲突。

### 2.4 原始点云负责判断，过滤点云负责写入

同一帧在程序中被分成两种用途。未经降采样和离群点过滤的有限原始点组成 `visibility_points`，用于构建射线最近回波；经过体素降采样和半径离群点过滤的点组成 `integration_points`，用于向地图写入新的障碍证据。

这种分工非常重要。若先把稀疏回波过滤掉，再用过滤结果判断自由空间，程序可能把“滤波器删掉了点”误认为“现实中没有障碍”。现在的设计让原始观测保留清图依据，同时只让相对可靠的点进入地图。用一句话概括，就是：写入障碍要克制，删除障碍要有证据。

## 3. 为什么实际效果会比较好

第一，重力对齐抑制了机身姿态带来的地面起伏，ODOM 补偿抑制了机器人运动带来的历史拖影。几何层先稳定，后面的证据累积才有意义。

第二，占用与清除采用不同时间尺度。新障碍一次可靠命中即可发布，重复命中会迅速增强；明确自由空间使用较强清除，而单纯无回波需要等待 5 帧确认。这种“快建立、慎删除”的非对称迟滞尤其适合安全优先的局部避障。

第三，遮挡被显式保护。前景出现新物体时，位于它后方的历史障碍不会因为当前帧看不见而被错误删除。当机器人换一个角度重新看到后方区域，地图再依据新的射线证据更新。

第四，算法没有固定帧窗口。静态障碍可以跨越较长时间保持，动态障碍又能被射线穿透证据快速清除。相比“固定累积 N 帧”，它把记忆长度交给观测质量，而不是交给一个统一帧数。

第五，实时策略优先保证信息新鲜。处理线程忙时，新点云会覆盖尚未处理的旧点云，系统不会为了补做过时数据而让延迟持续增长。对局部避障而言，一张略有丢帧但足够新的地图，通常比一张帧帧处理却已经落后的地图更有价值。

## 4. 关键参数的直观含义

当前地图的占用增益为 `1.0`，分数上限为 `6.0`，发布阈值为 `0.60`，删除阈值为 `0.15`。这意味着可靠的新体素可以很快进入输出，稳定体素则通过重复命中获得抗漏检能力。

明确自由空间的增益为 `1.4`，无回波确认后的弱自由增益为 `0.50`。当前实现先累加 `free_score`，再用累积后的自由分数扣减占用分数：

\[
F_t=\min(6,F_{t-1}+g),\qquad O_t=O_{t-1}-F_t.
\]

因此连续自由观测会产生加速清除，而不是每帧固定减去同一个数。这个行为有利于快速消除已经离开的动态障碍，但也比线性扣分更激进，是后续最值得单独做消融实验的部分。

当前同步允许点云、IMU 与 ODOM 时间相差不超过 `0.05 s`。若检测到 ODOM 单帧跳变过大，程序会清空历史地图，避免错误位姿把整张局部地图拉坏。这些阈值都不是普适常数，应当结合传感器频率、机器人速度和实测噪声重新标定。

## 5. 阅读源码的建议顺序

建议先看 [drdds_evidence_node.cpp](drdds_current/tools/drdds_evidence_node.cpp)。其中的 `processCloud()` 展示了点云、IMU、ODOM 如何同步，重力坐标怎样建立，以及原始点云如何被拆成可见性点集和融合点集。

随后看 [evidence_map.cpp](drdds_current/src/evidence_map.cpp)，按下面顺序阅读：

1. `processFrame()`：一帧数据的总流程；
2. `transformAndReindex()`：历史地图的运动补偿与重新体素化；
3. `buildVisibilityMaps()` 和 `projectToSensor()`：射线最近回波的建立；
4. `applyVisibilityEvidence()`：重合、自由、遮挡和无回波的分类；
5. `integrate()`：当前过滤点云如何写入证据；
6. `publishedVoxels()`：哪些体素最终能够发布。

数据结构和默认参数集中在 [evidence_map.hpp](drdds_current/include/m20_evidence_mapping/evidence_map.hpp)。[m20-drdds-evidence.service](deployment/m20-drdds-evidence.service) 则记录了 104 上的实际启动方式。`ros2_shadow` 是较早的 ROS 2 参考实现，适合用来比较算法演变，但学习当前运行逻辑时应以 `drdds_current` 为准。

## 7. 当前实现的边界

这套方法已经形成了完整而清晰的工程闭环，但仍有几个边界需要牢记。

其一，`last_hit_frame` 已被记录，却尚未参与基于年龄的淘汰。长期处于传感器视场之外或持续被遮挡的体素，可能比预期保留更久。若增加 TTL，也不宜只按时间粗暴删除，而应结合遮挡状态和传感器覆盖范围。

其二，当前自由证据采用累积分数扣减占用分数，会产生非线性加速。它可能正是动态残影消失较快的原因之一，也可能在某些边缘视场中增加误清除风险，应与线性版本进行同一 rosbag 下的对比。

其三，融合点云的半径离群点过滤可能削弱细杆、台阶尖角和远距离稀疏回波。针对这些高风险小目标，可能需要按距离自适应设置邻域条件，而不是全距离使用同一过滤标准。

其四，当前传感器模型没有独立的 `max_range` 约束，可见性保护半径默认也是 0。传感器有效距离、视场边缘和无回波语义需要结合厂商点云的数据契约进一步确认。

评价这套算法时，不应只看 RViz 中“点云是不是更浓”。更有意义的指标是首次检测延迟、静态障碍闪烁率、动态障碍残影时间、地面误障碍率、细小障碍召回率、处理耗时以及输出点数。只有在相同数据和相同区域上与单帧点云、固定 N 帧拼接等方法对比，才能定量说明每个机制的真实贡献。
