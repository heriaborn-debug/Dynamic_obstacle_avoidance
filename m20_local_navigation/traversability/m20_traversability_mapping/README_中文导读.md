# M20 NX 通行性分析

## 它解决什么问题

104 输出的 `/m20/local_mapping/evidence_cloud` 仍然是一张三维证据点云。它能说明空间中哪些位置持续存在可靠回波，却不会直接告诉规划器“这里是平地、坡面、台阶、低矮顶障碍，还是不能通行的突变区域”。

本模块运行在 NVIDIA NX 上，把三维证据点云转换成机器人中心的二维通行代价栅格，并额外发布一份只包含不可通行格子的障碍点云。FIRST 局部规划器使用这份障碍点云对 4641 条候选轨迹进行碰撞检查。

```text
/m20/local_mapping/evidence_cloud
                 ↓
        XY 高度柱与表面分层
                 ↓
    地面、顶面、净空和覆盖范围估计
                 ↓
       坡度、粗糙度、台阶高度
                 ↓
      通行代价计算与硬障碍判定
                 ↓
grid + terrain_cloud + obstacle_cloud
```

## 主要处理过程

### 1. 建立局部高程栅格

程序在机器人周围建立 `8 m × 8 m`、分辨率 `0.05 m` 的二维栅格。落在同一个 XY 格子中的三维点组成一根高度柱，点云 `intensity` 被解释为 104 证据地图给出的占用可信度。

同一高度柱内的 Z 值按 `0.10 m` 间隔进行聚类，以区分地面、台阶表面、悬空物和顶面。这样一个格子可以同时表达地面高度和机器人上方的障碍，而不是简单地只取最高点或最低点。

### 2. 自适应估计当前地面高度

程序在机器人附近区域统计每个高度柱的最低表面，使用稠密高度窗口的中位数作为当前地面参考。候选数量不足时才回退到默认值 `-0.48 m`。

这个设计使机器人高度或姿态发生小幅变化时，地面参考可以随当前点云自适应；少量地下噪点或墙面密集回波又不会轻易把地面基准拉偏。

### 3. 提取地面、顶面和净空

每个格子选择最接近地面参考的高度簇作为地面。如果最低可靠表面比地面参考高出超过 `0.25 m`，它会被视为缺少地面支撑的高物体，而不是可行走地面。

地面上方超过 `0.10 m` 的下一个高度簇被视为顶面或悬空障碍。其净空为：

\[
h_{\mathrm{clear}}=z_{\mathrm{ceiling}}-z_{\mathrm{ground}}.
\]

当净空小于 `0.50 m` 时，该格子直接判定为不可通行。这能识别桌板、横梁或其他机器人无法从下方通过的结构。

### 4. 只修补可信的小孔洞

点云中的空白不会直接被当成自由空间。程序只填补完全被已知地形包围、面积不超过 200 个格子、边界不少于 6 个格子且边界高度差小于 `0.10 m` 的小孔洞。

因此，局部漏点可以得到平滑补偿，但与地图边缘相连的大块未知区域仍保持未知或较高代价，不会凭空生成可通行地面。

### 5. 判断传感器是否真正覆盖该位置

程序根据前后雷达在机器人上的位置，沿栅格射线检查目标格子是否具有连续地形支持。射线中连续未知区域超过 3 格时，该目标不再认为是可靠覆盖区域。

机器人中心 `0.80 m` 半径内由于本体遮挡形成的盲区使用显式地面填充，避免机器人脚下出现无法解释的空洞。该填充会被单独标记，不与真实观测混淆。

### 6. 计算坡度、粗糙度和台阶

程序在每个格子的 `3 × 3` 邻域内拟合局部平面：

\[
z=ax+by+c.
\]

坡度由平面法向得到：

\[
\theta=\arctan\sqrt{a^2+b^2}.
\]

粗糙度是邻域点到拟合平面的均方根残差，台阶高度则是当前格子与八邻域之间的最大高度差。三者分别描述持续倾斜、表面起伏和局部突变。

### 7. 生成通行代价与硬障碍

普通地形代价由坡度、粗糙度和台阶高度加权组成：

\[
C=90\left(0.30C_{\mathrm{slope}}+0.30C_{\mathrm{rough}}+0.40C_{\mathrm{step}}\right).
\]

输出栅格中，低代价值表示更容易通过，`90` 表示硬障碍，未充分观测或指标不足的位置至少赋予 `20` 的保守代价。出现以下任一情况时会直接判为硬障碍：

- 净空小于 `0.50 m`；
- 缺少地面支撑的高表面；
- 坡度达到物理上限；
- 粗糙度超过上限；
- 台阶高度超过允许范围。

当前 `inflation_radius=0`，因为 FIRST 的轨迹—栅格对应模板已经包含机器人扫掠体积。如果这里再次膨胀，会造成双重安全边界，使可通行区域被不必要地压缩。

## 输出接口

- `/m20/local_mapping/traversability/grid`：完整二维代价栅格；
- `/m20/local_mapping/traversability/obstacle_cloud`：硬障碍格子的中心点，供 FIRST 碰撞检查；
- `/m20/local_mapping/traversability/terrain_cloud`：所有已知地形格子，`intensity` 保存代价；
- `/m20/local_mapping/traversability/diagnostics`：处理时间、未知格、坡度/粗糙度/台阶异常数量和输入超时状态。

## 阅读源码

建议依次阅读：

1. `config/m20_traversability_mapping.yaml`：完整实机参数；
2. `include/m20_traversability_mapping/traversability_grid.hpp`：格子状态和统计结构；
3. `src/traversability_grid.cpp`：表面提取、覆盖判断、地形指标和分类；
4. `src/traversability_mapping_node.cpp`：ROS 2 输入输出；
5. `test/test_traversability_grid.cpp`：平地、台阶、低净空和孔洞修补测试；
6. `deploy/m20-traversability-mapping.service`：NX systemd 部署配置。

## 边界说明

这是一套基于局部几何规则的确定性通行性分析，而不是学习模型。优点是含义清楚、容易调试、能够直接解释每个障碍格子的来源；边界是阈值依赖机器人尺寸和点云质量，对松软地面、湿滑程度、可踩踏植被等非几何属性没有直接判断能力。
